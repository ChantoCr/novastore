# Documentation Skill — NOVA Store

## Purpose
Use this skill when writing or updating README, architecture notes, API docs, setup instructions, and portfolio explanation.

## README Must Include
- Project title
- Project description
- Features
- Tech stack
- Screenshots
- Architecture overview
- Folder structure
- Installation
- Environment variables
- Database setup
- Demo users
- API endpoints
- Development phases
- Security decisions
- Testing instructions
- Docker instructions
- Future improvements

## Portfolio Explanation
The project should be presented as:

A fullstack e-commerce platform focused on secure authentication, role-based access, admin workflows, Redux-powered cart management, simulated checkout, auditability, and professional frontend experience.

## Important Documentation Sections
- Why this project exists
- What problem it solves
- What makes it different from a basic e-commerce demo
- Main technical decisions
- Security decisions
- Screenshots
- How to run locally
- How to test

## Rules
- Keep docs aligned with the actual codebase.
- Update documentation when architecture changes.
- Prefer examples over vague explanations.
- Write for both recruiters and technical reviewers.

## Avoid
- Empty README.
- Generic descriptions.
- Missing setup steps.
- Missing environment variable examples.
- Not explaining architecture decisions.
